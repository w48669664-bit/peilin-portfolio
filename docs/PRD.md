# 谢沛霖 · 沉浸式个人网站

> 产品需求文档 v1.0 · 2026-09-25  
> 用途：交给 AI 或开发者实施的新站规格。本文件为开发规格；实现与验收状态参见项目 README.md 和 design-qa.md。  
> 基准：用户录屏 + 已上线个人作品集 `32f350c`。新站与原站分别维护。

## 1. 要做成什么

做一个以真实感水面为入口的个人网站。访客能在水面上触发涟漪，调节一天中的时间，观察晨光、日光、黄昏、月夜的连续变化，并自主开启环境音乐。点击“关于我”“作品集”时，在同一个视觉空间里打开个人信息和作品内容。

网站主角是谢沛霖。录屏用于参考空间感、交互和节奏；姓名、介绍、履历、奖项、项目与联系方式使用原个人网站已经确认的内容。

**一句话开发目标：复现录屏的水面交互与内容展开方式，把内部内容替换为谢沛霖的真实简历和六个作品，作为一个独立新站发布。**

### 产品成功标准

- 初次进入即可看见真实感水面、个人署名和清晰的内容入口。
- 点击或触摸水面能看到由该位置产生、扩散并衰减的涟漪。
- 调节时间会改变水面光照与反射；控制器不是仅改变时间数字。
- 不离开新站即可阅读完整履历与六个项目，每个项目三张真实截图能原地翻页。
- 访客可在两次点击内从首页进入某个项目详情，或直接下载简历。
- 动画或音频不可用时，仍能查看简历、作品和联系方式。
- 原站继续正常访问；新站有独立仓库、部署流程与网址。

## 5. 功能要求

### F01 — 水面首页（必须）

**构图**：水面铺满浏览器可用区域，近景可见不规则圆石，向远处逐渐减弱；中央略偏左有拉长的光带。整体为斜向俯视的近岸水面，不改成有山峰和天空的大幅风景照。

**信息分布**：左上显示 `Peilin.` 或“谢沛霖”；左侧中部显示时间、“关于我”“作品集”；右侧中部放小型音乐控制；底部放当前时段与极短说明。另提供明确可见的简历下载入口。不要把所有内容挤在中央。

**状态**：首次打开默认与访客设备当地时间同步，明确为本地时间，不请求定位。资源加载时立即显示署名和内容入口，并先展示静态水面。加载失败时保留静态画面和全部内容入口。

**验收**：无论动效是否加载成功，访客都能进入作品和简历。页面没有必须等待结束的开场动画或强制“进入网站”门槛。

### F02 — 水面涟漪（必须）

- 无操作时存在轻微、持续、非机械重复的水流。
- 桌面鼠标移动产生低强度扰动；按下时在落点产生更明显的单次涟漪。触屏以轻触触发。
- 波纹影响局部折射与高光，扩散后衰减，不用画在页面上的普通 CSS 圆圈冒充水波。
- 近处涟漪更清楚，远处适当压缩，方向与水面透视一致。
- 指针在导航、播放器或内容面板上操作时，不向水面注入扰动。
- 首轮建议：响应延迟低于 100ms，波纹在 2–4 秒内衰减；这些是待调试目标，不是从录屏测出的参数。
- 限制同时存在的扰动与移动采样频率；连续滑动不得让画面越积越亮或严重掉帧。

### F03 — 时间与光照（必须）

点击首页时间，出现类似录屏的中央“光影时刻”控制层。包含当前选择时间、竖向刻度、四个时段按钮、回到现在、关闭。

| 模式 | 建议锚点 | 视觉方向 |
| --- | --- | --- |
| 晨光 | 06:30 | 冷灰蓝向柔暖色过渡，较低强度反光 |
| 日间 | 12:00 | 更清澈明亮，石头可见，避免纯白过曝 |
| 黄昏 | 18:40 | 琥珀色、铜色反射，暗部保持深度 |
| 月夜 | 23:00 | 深蓝灰水面，细长银色高光 |

锚点是新站设计值，需结合最终场景调色。四时段之间连续插值，不是四张背景硬切或只加全屏色块。

**输入**：拖动刻度、焦点在刻度时滚轮微调、键盘方向键、点击时段按钮。界面同时支持 24 小时时间文本输入作为可访问替代。时间为 0–1439 分钟循环，跨午夜无跳变；细调步长建议 5 分钟。

**规则**：自动模式每分钟更新；用户拖动或选时段后进入手动模式，关闭浮层仍保留选定光照；“回到现在”恢复自动模式。刷新恢复自动模式，以免访客误认上次选定时间为当前时间。

**视觉反馈**：操作刻度时数字与光照同步响应，切换预设采用约 600–1000ms 的过渡。简历或作品面板中的滚轮只滚动正文，不能改变背景时间。

### F04 — 环境音乐与轻反馈（必须有真实控制）

- 首页右侧提供播放/暂停、上一首、下一首和音量，曲目标题与真实资源一致。
- 建议准备三段原创或可使用的无歌词环境音乐，默认静音；首次由用户明确点击播放后启动。
- 音量支持键盘操作；切曲采用短淡入淡出，禁止两首无限叠播。
- 进入作品或简历时维持用户音量状态；如果播放项目视频，则暂时暂停背景音乐，视频结束后只在用户先前主动开启过音乐时恢复。
- 切到后台暂停动态渲染并暂停音乐；返回后由明确规则恢复画面，音乐保持暂停，避免意外出声。
- 文件加载失败展示“音频暂不可用 / 重试”，按钮不能假装播放成功。
- 刻度的轻微“咔哒”反馈属于可选增强。仅在用户启用声音后、离散步进时触发并限频；本次录屏无音轨，不能承诺与参考听感一致。

音频不得从录屏中截取；使用明确来源的素材或新创作的音频，并记录来源。浏览器对自动播放有限制，实现参考 [MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。

### F05 — 关于我与完整简历（必须）

关于我面板采用居中标题、短介绍、证件照和少量清晰入口，背景水面变暗并模糊。开头直接用姓名，不恢复“我是谢沛霖”。中文为主，英文作辅助。

提供“完整简历”“查看作品”“下载 PDF”。完整简历是独立、宽敞的阅读视图：沿用旧版的个人信息在左、教育背景在右的紧凑开头，随后为能力优势、自我评价、实习、技能、荣誉、联系。

详细文字放在稳定的不透明或高不透明度表面上，不直接叠到闪烁的反光上。实习项目保持展开，统一显示突出成果。课程放在两校共同区域。页面内部有章节锚点，可快速到实习与技能。

### F06 — 作品目录与详情（必须）

目录包含以下六项，不替换成参考视频中的三个示例项目：

| 项目 | 一句话定位 | 三张截图 |
| --- | --- | --- |

**媒体事实**：交易截图为示例账户；FlowQuant 为演示数据；Colla Agent 为历史运行。不得误标实时、生产成果或收益证明。WorkRelay 的已有演示视频按需加载。

### F07 — 面板与页面状态（必须）

- 同一时间只存在一个主内容面板；项目大图可以作为其上层，但应有清晰的返回路径。
- 打开面板时锁定背景滚动，正文自身滚动；关闭后恢复原位置。
- 右上关闭按钮与 Escape 均可退出，关闭后焦点回到进入按钮。
- Tab 焦点限制在当前对话层；后台内容不可被无意点击或键盘访问。
- 从作品列表进入详情再返回，保留列表位置；从关于我跳到作品目录时避免重复堆叠面板。
- 刷新 `#/work/lumiframe` 可直接显示对应内容；未知 ID 显示友好提示与返回作品目录。

## 6. 视觉与动效规范

### 6.1 复刻重点

优先级依次为：**水面真实感 → 光影变化 → 指针交互 → 页面构图 → 转场 → 信息可读性与内容完整度**。内容完整度是交付底线，不能因视觉优先而删减简历。

保留参考的安静、克制、留白与小体量导航。首页不放巨大的营销标题、滚动代码雨、霓虹光圈或大量悬浮卡片。

入口的英文署名和氛围标题可用细衬线字体；中文履历正文使用清晰无衬线字体。最终字库应自托管并有系统字体回退。英文装饰文字不要取代中文功能按钮。

### 6.2 布局与字体

| 项目 | 建议规格（实现时可小幅调整） |
| --- | --- |
| 桌面页面边距 | 40–56px，随宽度缩放 |
| 首页左侧入口 | 距左边约 5vw，位于垂直中部附近 |
| 内容层最大宽度 | 关于我 720px；履历与作品详情 1120–1240px |
| 中文正文 | 桌面 16–17px，手机 16px，行高 1.8–2.0 |
| 次要说明 | 13–14px；必要操作不低于 14px |
| 操作目标 | 点击区域至少 44×44px，图形可更小 |
| 正文对比度 | 普通文字至少 4.5:1，焦点状态清楚可见 |
| 内容层动效 | 约 250–400ms 的淡入、轻微位移；避免大幅缩放 |
| 背景光照过渡 | 约 600–1000ms；拖动时连续跟手 |

### 6.3 手机适配

- 以 `100dvh` 与安全区适配，不照搬桌面左中右三列。
- 署名位于顶部，关于我/作品集/简历入口在稳定可触达的位置，时间和音乐使用紧凑控制。
- 作品与简历以接近全屏的阅读层展示，不做窄小悬浮窗。
- 水面触摸只在空白区域生效；截图横滑不能阻止正文竖向滚动。
- 不隐藏核心履历，也不通过无限缩小字体塞满屏幕。

## 7. 技术实施建议与素材要求

以下是建议实现路线，不是对参考站技术的断言。先用短周期画面验证，再定最终水面实现。

### 7.1 推荐结构

- React + TypeScript + Vite：UI、内容面板与本地状态。
- WebGL 水面层：可用 Three.js 管理场景，定制着色器处理折射、反射、光照与波纹。
- 独立 `WaterScene`、`TimeController`、`AudioPlayer`、`OverlayRouter`、`ResumeView`、`ProjectGallery`。
- 数据从结构化内容文件读取；场景时间、面板状态、音乐状态相互独立。
- 高频水面参数留在渲染循环中，不以每帧 React state 更新整个页面。
- 页面无需数据库、账号、付费模型 API 或后台管理；音乐和图片使用本地静态资产。

### 7.2 水面实现路线比较

| 路线 | 优点 | 局限 | 建议 |
| --- | --- | --- | --- |
| 真实感底图/纹理 + WebGL 折射与交互扰动 | 易于控制构图，资源与性能可控，可支持四时段 | 反射和透视需精调，否则像图片扭动 | 首选验证路线 |
| 三维水面、石头场景与实时光照 | 空间与交互自由度高 | 美术、着色与性能成本更高 | 首选路线不足时升级 |
| 仅循环视频背景 | 静态观感容易接近 | 无法自然支持任意时间与落点扰动 | 只能作降级或临时素材预览，不满足最终验收 |

先完成 10–15 秒静止、点击水面、跨时段切换的视觉验证。若水面只是模糊渐变、普通圆圈或重复闪动，不能进入“完成”状态。

### 7.3 新增资产清单

| 资产 | 当前状态 | 完成条件 |
| --- | --- | --- |
| 原站个人内容与六个项目媒体 | 已有 | 直接复用与校验 |
| 正式水面底图/纹理与静态降级图 | 尚未准备 | 原创生成或可用素材，构图对照录屏，来源记录 |
| 水面法线/噪声资源 | 尚未准备 | 可程序化生成或使用明确来源纹理 |
| 三段环境音乐 | 尚未准备 | 实际音频文件、标题、来源与授权信息齐全 |
| 刻度短音效 | 尚未准备，可选 | 低音量、短时长、可全局静音 |

素材包里的参考帧不应直接用于填补以上缺口。生成式工具可以准备新的水面底图，但不能保证第一次生成即达到参考效果，需要对照调整。

### 7.4 性能与失败兜底

- 首屏先出静态底图与导航，WebGL 和音乐按需启动；作品图片只在需要时加载。
- 初始媒体预算建议不超过 4MB，不含按需音频和作品；图片优先 WebP/AVIF。
- 桌面目标接近 60fps，中端手机至少稳定 30fps；在测试报告中记录设备、浏览器和实际表现，不能只凭感觉声称流畅。
- 限制像素比、纹理尺寸与波纹模拟分辨率；低性能时减少细节。
- 支持 `prefers-reduced-motion`：静态或极弱动效，并提供“减少动效”控制。
- WebGL 不可用、上下文丢失或资源加载失败时，切换静态背景；内容页面仍正常使用。
- 渲染错误不得清空整个 React 应用；切到后台停止不必要的逐帧工作。

WebGL 实施参考 [MDN WebGL 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。
